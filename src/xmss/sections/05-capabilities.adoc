
[[prereq_algs]]
=== Required Prerequisite Algorithms for XMSS Validations

Each XMSS implementation relies on other cryptographic primitives. For example, XMSS sigGen uses an underlying SHA algorithm. Each of these underlying algorithm primitives must be validated, either separately or as part of the same submission. ACVP provides a mechanism for specifying the required prerequisites:

[[rereqs_table]]
.Required XMSS Prerequisite Algorithms JSON Values
|===
| JSON Value | Description | JSON Type | Valid Values

| algorithm | a prerequisite algorithm | string | SHA, or DRBG
| valValue | algorithm validation number| string | Actual number or "same"
| prereqAlgVal | prerequisite algorithm validation | object with algorithm and valValue properties | See above
|===

=== XMSS Algorithm Registration Properties

Each XMSS algorithm capability advertised is a self-contained JSON object using the following values.

[[XMSS_caps_table]]
.XMSS Algorithm Capabilities JSON Values
|===
| JSON Value | Description | JSON Type | Valid Values

| algorithm | The XMSS algorithm to be validated | string | See <<supported>>
| mode | The XMSS mode to be validated | string | See <<supported>>
| revision | The algorithm testing revision to use | string | See <<supported>>
| prereqVals | Prerequisite algorithm validations | array of prereqAlgVal objects | See <<prereq_algs>>
| capabilities | The XMSS parameter sets that are supported | object | See <<capability_details>>
| messageLength | The message lengths supported by the implementation. | domain | Min: 8, Max: 65536, Increment: Any
|===

The capabilities advertised by the module must use the following JSON object schema. The ACVP server *MAY* select any values from the array to test.

An XMSS parameter set fully determines the parameters of the underlying WOTS+ one-time signature scheme, so only a single array of parameter sets is registered.

[[capability_details]]
.XMSS Capability Details
|===
| JSON Value | Description | JSON Type | Valid Values

| xmssModes | An array of XMSS parameter sets supported | array of strings | See <<valid_xmss_modes>>
|===

[#valid_xmss_modes]
==== Valid XMSS Modes

The following parameter sets approved by <<SP800-208>> for the XMSS scheme of <<RFC8391>> *MAY* be registered by the module.

* XMSS-SHA2_10_256
* XMSS-SHA2_16_256
* XMSS-SHA2_20_256
* XMSS-SHA2_10_192
* XMSS-SHA2_16_192
* XMSS-SHA2_20_192
* XMSS-SHAKE256_10_256
* XMSS-SHAKE256_16_256
* XMSS-SHAKE256_20_256
* XMSS-SHAKE256_10_192
* XMSS-SHAKE256_16_192
* XMSS-SHAKE256_20_192
